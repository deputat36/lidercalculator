# Связка сайта РА «Лидер» и CRM v4

Дата: 18.06.2026

Документ фиксирует текущую рабочую схему прохождения заявки с сайта в CRM и удобный порядок обработки менеджером.

## 1. Общая цепочка

1. Клиент заходит на сайт РА «Лидер».
2. Оставляет заявку через публичную форму.
3. Форма отправляет данные в Supabase Edge Function `leader-public-lead`.
4. Edge Function создаёт запись в таблице `leader_leads`.
5. Менеджер видит заявку в CRM v4 в разделе «Заявки».
6. В карточке заявки менеджер видит блок «Данные с сайта для менеджера».
7. Менеджер может одной кнопкой создать потребность из данных сайта.
8. Менеджер ставит следующий контакт и фиксирует дальнейшие действия.
9. После уточнения менеджер создаёт расчёт, формирует КП и при согласовании создаёт заказ.
10. Заказ передаётся в производство и/или монтаж.

## 2. Публичная форма сайта

Основной файл формы:

`assets/public-lead-form.js`

Актуальная версия на странице заявки:

`assets/public-lead-form.js?v=4`

Форма должна собирать:

- имя / организация;
- телефон;
- услуга;
- описание задачи;
- город;
- удобный способ связи;
- количество / формат;
- срок;
- статус макета;
- доставка / монтаж;
- ориентировочный бюджет;
- бизнес / объект;
- страницу и URL;
- UTM-метки.

## 3. Способы связи

Актуальные варианты:

- Позвонить;
- Написать в MAX;
- Написать ВКонтакте;
- Написать на email;
- Любой удобный способ.

WhatsApp и Telegram в форме сайта не используются как основные варианты связи.

## 4. Edge Function

Функция:

`leader-public-lead`

Текущая версия после обновления:

`v4`

Режим:

`verify_jwt = false`

Это важно: функция принимает заявки с публичного сайта, где пользователь не авторизован в Supabase.

Функция пишет в `leader_leads`:

- `name`;
- `phone`;
- `service`;
- `source`;
- `message`;
- `page_url`;
- `city`;
- `contact_preference`;
- `status = Новая`;
- UTM-поля;
- `payload`.

В `payload` сохраняются:

- `form = site_public_form_v4`;
- `page_title`;
- `city`;
- `business`;
- `contact_method`;
- `quantity`;
- `deadline`;
- `mockup`;
- `delivery`;
- `budget_label`;
- `user_agent`;
- `referer`.

## 5. CRM: список заявок

Добавлен модуль:

`assets/v4/site-crm-workflow-v1.js`

Он добавляет блок «Сайт ↔ CRM» в раздел «Заявки».

Блок показывает:

- всего заявок;
- сколько заявок с сайта;
- сколько новых заявок с сайта;
- сколько заявок без следующего контакта;
- сколько заявок без телефона.

Быстрые фильтры:

- Показать заявки с сайта;
- Новые с сайта;
- Без следующего контакта;
- Без телефона;
- Сбросить фильтр;
- Обновить заявки.

Заявки с сайта подсвечиваются. Заявки с сайта без телефона выделяются как проблемные.

## 6. CRM: карточка заявки

Добавлены модули:

- `assets/v4/lead-site-summary-v1.js`;

Блок «Данные с сайта для менеджера» показывает:

- количество / формат;

Быстрые действия:

- открыть страницу заявки;

- поставить следующий контакт на завтра;
- обработать заявку без телефона отдельным статусом.

## 7. Создание потребности из данных сайта

Кнопка:

`Создать потребность из данных сайта`

Создаёт запись в таблице:

`leader_lead_needs`

Переносит из заявки:

- услугу;
- описание;
- бизнес / объект;
- страницу заявки;
- удобный способ связи;
- количество / формат;
- срок;
- макет;
- доставка / монтаж;
- бюджет;
- город;
- признаки «нужен дизайн» и «нужен монтаж».

Тип потребности определяется автоматически:

- баннер → `Баннер`;
- вывеска → `Вывеска`;
- плёнка / наклейки → `Пленка / наклейки`;
- табличка → `Табличка`;
- дизайн / макет → `Дизайн`;
- монтаж → `Монтаж`;
- соцсети / карты / 2ГИС → `Интернет-реклама`;
- иначе → `Другое`.

Если потребность из сайта уже создана, кнопка становится неактивной и повторно дубль не создаёт.

## 8. Следующий контакт из блока сайта

Кнопка:

`Поставить контакт на завтра`

Работает только внутри блока `#leadSiteSummaryBox`, чтобы не конфликтовать со штатными кнопками следующего контакта в основной карточке заявки.

Действие:

- ставит `next_contact_at` на завтра в 10:00;
- если заявка новая, переводит её в статус `В работе`;
- обновляет список заявок и текущую карточку;
- пытается записать событие в `leader_lead_events`, но ошибка события не ломает основное действие.

## 9. Удобный порядок обработки заявки

1. Открыть раздел «Заявки».
2. Нажать «Новые с сайта».
3. Открыть первую заявку.
4. Проверить блок «Данные с сайта для менеджера».
5. Если телефона нет — обработать отдельно: посмотреть email или другие данные в сообщении / payload.
6. Позвонить или написать выбранным способом связи.
7. Нажать «Создать потребность из данных сайта».
8. Проверить созданную потребность и дополнить недостающие детали.
9. Нажать «Поставить контакт на завтра» или выбрать другую дату в основной карточке.
10. Создать расчёт.
11. Сформировать КП.
12. После согласования создать заказ.
13. Передать заказ в производство / монтаж.

## 10. Контрольные проверки

После изменений нужно проверить:

1. `https://www.lider-bsk.ru/request.html?form-v4=20260618`
2. Форма раскрывает подробные поля.
3. В форме есть MAX, ВКонтакте, email, бюджет, бизнес / объект.
4. Тестовая заявка создаётся в `leader_leads`.
5. В CRM заявка появляется в разделе «Заявки».
6. В списке заявок она подсвечивается как заявка с сайта.
7. В карточке заявки появляется блок «Данные с сайта для менеджера».
8. В поле «Связь» отображается выбранный способ связи.
9. Данные в `payload` содержат `form = site_public_form_v4`.
10. Кнопка «Создать потребность из данных сайта» создаёт запись в `leader_lead_needs`.
11. Кнопка «Поставить контакт на завтра» обновляет `next_contact_at`.

## 11. Что нельзя ломать

- Не отключать `verify_jwt=false` у `leader-public-lead`, пока форма публичная.
- Не отправлять текстовый бюджет в числовое поле `budget` без преобразования.
- Не удалять `payload`, потому что там хранятся расширенные данные формы.
- Не убирать `page_url`, иначе менеджер не поймёт, с какой страницы пришёл клиент.
- Не возвращать WhatsApp/Telegram как основные способы связи без отдельного решения.
- Не перехватывать все `[data-next-contact="tomorrow"]` глобально: штатная карточка заявки уже использует этот атрибут.

## 12. Следующие улучшения

Рекомендуемые следующие шаги:

1. Массово поднять версию `public-lead-form.js` на всех посадочных страницах, когда будет безопасный патчевый инструмент или локальная сборка.
2. Добавить отдельную страницу / раздел CRM «Заявки с сайта» при росте количества обращений.
3. Добавить автоуведомление о новой заявке в Telegram или MAX для ответственного менеджера.
4. Добавить контроль дублей по телефону.
5. Добавить шаблоны первого ответа по типу услуги.
6. Добавить автоматическую постановку первичной задачи менеджеру по новой заявке с сайта.
