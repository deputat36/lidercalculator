# CRM v4 — полный аудит и доработки от 17.06.2026

## Цель аудита

Проверить текущую CRM v4 для РА «Лидер» после серии доработок: карточка заявки, расчёты, КП, заказы, клиенты, редакторы сущностей, нагрузка на Supabase и структура подключенных модулей.

## Что было найдено

### 1. Дублирование редактора заявки

В проекте одновременно работали два редактора заявки:

- старый встроенный `lead-edit.js`;
- новый универсальный редактор `entity-edit-v2.js`.

Это могло давать дублирующиеся кнопки, путаницу в карточке и лишний визуальный шум.

Что исправлено:

- `lead-edit.js` отключён из `app-v4.html`;
- вместо него используется новый универсальный редактор `entity-edit-v3.js`;
- в `lead-card-layout-fix.js` оставлена защитная очистка старых элементов `editLeadBtn` и `leadEditBox`, если они остались в кэше браузера.

### 2. Карточка заявки была перегружена

Карточка заявки сразу раскрывала все рабочие блоки:

- сообщение клиента;
- потребности;
- сохранённые расчёты;
- типовой расчёт;
- нестандартный расчёт;
- КП;
- ссылки и источник;
- технические данные формы.

Это мешало быстро понять, что делать с заявкой.

Что исправлено:

- добавлен модуль `lead-card-accordion.js`;
- рабочие блоки карточки переведены в сворачивающиеся секции;
- открыты по умолчанию только основные блоки: сообщение клиента, потребности, сохранённые расчёты;
- типовой расчёт, нестандартный расчёт, КП, ссылки и технические данные по умолчанию свернуты.

### 3. Риск неправильного порядка блоков после аккордеона

После оборачивания блоков в `<details>` была вероятность, что скрипт перестановки перенесёт внутренний блок вместо визуального блока-аккордеона.

Что исправлено:

- `lead-card-layout-fix.js` теперь работает с визуальным блоком через `closest('details[data-lead-accordion="1"]')`;
- порядок блоков сохраняется безопасно:
  1. сохранённые расчёты;
  2. быстрый типовой расчёт;
  3. нестандартный расчёт;
  4. КП.

### 4. Старый калькулятор был убран из карточки

Ранее в карточке заявки визуально было два расчётных блока: старый калькулятор и новый быстрый/нестандартный расчёт.

Что исправлено:

- `calculations-catalog.js` больше не подключается к `app-v4.html`;
- вместо него используется `calculations-saved-tools-v2.js`, который показывает только сохранённые расчёты;
- создание новых расчётов вынесено в отдельные понятные блоки:
  - `calculations-standard.js` — типовые позиции;
  - `calculations-advanced.js` — нестандартные позиции.

### 5. Лишние фоновые запросы редактора

`entity-edit-v2.js` использовал постоянный `setInterval(enhance, 2200)`, из-за чего каждые 2,2 секунды могли запускаться проверки списков для добавления кнопок редактирования.

Что исправлено:

- создан `entity-edit-v3.js`;
- постоянный таймер убран;
- редактор обновляет кнопки только по событиям:
  - готовность CRM;
  - открытие карточки заявки;
  - смена маршрута;
  - клик по вкладке;
  - обновление списка.

### 6. Дублирующиеся индексы в Supabase

Supabase Performance Advisor показал дубли индексов в таблицах CRM «Лидер».

Удалены безопасные дубли:

- `leader_lead_needs_lead_id_idx`;
- `leader_lead_needs_status_idx`;
- `idx_leader_leads_next_contact_at`;
- `idx_leader_leads_status_created_desc`.

Оставлены основные аналоги:

- `idx_leader_lead_needs_lead_id`;
- `idx_leader_lead_needs_status`;
- `idx_leader_leads_next_contact`;
- `idx_leader_leads_status_created`.

### 7. Supabase API-логи

Проверены API-логи Supabase. По CRM-запросам видны в основном ответы `200` и `201`. Критических ошибок уровня `500` по основному сценарию не обнаружено.

## Что осталось как технический долг

### 1. Inline-скрипт переключения вкладок в `app-v4.html`

Внизу `app-v4.html` ещё есть старый inline-скрипт переключения вкладок. Сейчас он не мешает из-за `main-menu-fix.js`, но лучше позже вынести вкладки полностью в отдельный модуль и убрать inline-код.

### 2. RLS performance warnings

Supabase показывает предупреждения по RLS-политикам, где функции `auth.*` могут вычисляться построчно. Это не авария, но на большой базе может замедлять запросы.

Нужно позже отдельно пройтись по политикам только `leader_*` и заменить вызовы на формат `(select auth.uid())` / `(select auth.email())`, где это безопасно.

### 3. SECURITY DEFINER warnings

Supabase показывает предупреждения по `SECURITY DEFINER` функциям. Для части `leader_*` это ожидаемо, потому что функции используются для CRM-операций. Но позже нужно отдельно пройтись по правам `EXECUTE` и оставить доступ только там, где он действительно нужен.

`nav_*` и `nav_v2_*` не трогались, потому что это другой проект.

### 4. Полноценные карточки клиента и КП

Редактирование клиента и КП уже есть, но полноценные отдельные карточки клиента и КП пока не реализованы. Следующий логичный этап:

- карточка клиента: все заявки, все КП, все заказы, история контактов;
- карточка КП: состав, печать, история статусов, связь с расчётом и заказом.
