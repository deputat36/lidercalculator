# CRM v4 — журнал стабилизации 18.06.2026

## Цель

Стабилизировать вход, загрузку данных, роли, права доступа и безопасно вернуть полезные блоки сайта в CRM.

## Сделано в этом этапе

### 1. Безопасный блок заявки с сайта

Добавлен файл:

`assets/v4/lead-site-summary-safe-v1.js`

Что делает:

- показывает в карточке заявки блок «Данные заявки с сайта»;
- берёт данные только из уже загруженной `v4State.currentLead`;
- не делает дополнительных запросов к Supabase;
- не использует `MutationObserver`;
- не создаёт потребности;
- не меняет статусы;
- не перехватывает штатные кнопки.

Подключён через:

`assets/v4/lead-card-layout-fix.js`

Версия подключения в `app-v4.html` поднята до:

`lead-card-layout-fix.js?v=20260618-8`

Коммиты:

- `99a8b75b0987bd991a4819ed3c63872aad3fd7aa`
- `4697e04580f6c7437d522d50f9c72403d4f609df`

### 2. Режим просмотра номенклатуры для не-админов

Добавлен файл:

`assets/v4/catalog-view-mode-v1.js`

Что делает:

- если роль не `owner` и не `admin`, показывает предупреждение:
  - «Режим просмотра: изменение цен и номенклатуры доступно только владельцу или администратору.»
- скрывает кнопку добавления позиции;
- скрывает кнопки сохранения;
- переводит поля номенклатуры в readonly/disabled.

Важно:

это только интерфейсное ограничение. Главная защита уже сделана на уровне Supabase RLS.

Коммиты:

- `a5d006d46af18e82430aec623b738b33b9d14550`
- `0857367b6ae10b912a21b50bd153cfd265540be0`

### 3. Серверная защита номенклатуры

В Supabase RLS изменены политики `leader_catalog`:

- SELECT — всем активным пользователям CRM;
- INSERT — только `admin / owner`;
- UPDATE — только `admin / owner`;
- DELETE — только `admin / owner`.

Также ограничена запись в `leader_catalog_price_logs`:

- INSERT — только `admin / owner`.

Удалена опасная политика:

`leader_profiles_update_self`

Теперь пользователь не может сам обновлять свой профиль и потенциально менять себе роль.

### 4. Supabase advisors

Проверены:

- Security advisor;
- Performance advisor.

Выводы:

- большинство security warnings относится к отдельному проекту `nav_v2_*`, его в рамках CRM не трогали;
- по `leader_*` есть ожидаемые предупреждения на SECURITY DEFINER функции, которые используются для RLS/профиля/создания заказа;
- performance warnings в основном касаются старых таблиц и неиспользуемых индексов;
- при текущем объёме данных удалять индексы не нужно.
