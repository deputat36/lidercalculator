## 1. Краткий вывод

Проблема не в самом Supabase Auth и не в RLS основных CRM-таблиц.

По логам Supabase пользователь `kvmbsk@yandex.ru` успешно входит, профиль CRM создан, запросы к основным таблицам CRM проходят со статусом `200`.

Основные причины сбоев:

1. В браузере были старые/битые сессии Supabase: в логах есть много `Invalid Refresh Token: Refresh Token Not Found`.
2. Были подключены экспериментальные фронтенд-надстройки сайта, которые импортировали базовые модули CRM повторно и могли создавать циклы/дубли обработчиков.
3. Был конфликт двух модулей управления вкладками: `responsive-ui.js` и `main-menu-fix.js`.
4. В API-логах рядом с CRM видна ошибка `nav_v2_get_dashboard` со статусом `502`; это не CRM v4, а отдельный проект «Навигатор», но он использует тот же Supabase-проект и может путать диагностику.

## 7. Проблема старых сессий и localStorage

В `assets/v4/config.js` для CRM используется отдельный ключ хранения:

`leader_crm_v4_session`

Это хорошо: CRM v4 не должна использовать стандартный Supabase storage key.

Но на домене `deputat36.github.io` есть другие приложения, которые тоже работают с тем же Supabase-проектом. Если они используют стандартный storage key Supabase, в браузере могут оставаться старые токены и происходить ошибки refresh token.

Рекомендация:

1. Для чистой проверки использовать инкогнито.
2. На рабочем браузере очистить localStorage для `deputat36.github.io`.
3. В дальнейшем для каждого приложения использовать отдельный storage key.

Задача сейчас — добиться стабильной базовой CRM, затем возвращать эти helpers по одному.

## 9. Главный фронтенд-конфликт №2: два управляющих меню

В CRM одновременно работали:

- `responsive-ui.js` — создаёт секции и загружает списки вкладок;
- `main-menu-fix.js` — перехватывал клики по вкладкам.

Это могло приводить к ситуации:

- кнопка нажалась;
- один модуль открыл вкладку;
- второй модуль тут же перехватил управление;
- секция не успела создаться или загрузиться;
- пользователь видит зависание / пустую вкладку / ошибки Supabase.

Исправление уже внесено:

`main-menu-fix.js` теперь перехватывает только вкладку `Производство`, а обычные вкладки ведёт `responsive-ui.js`.

Версия в `app-v4.html` поднята до:

`main-menu-fix.js?v=20260618-4`
