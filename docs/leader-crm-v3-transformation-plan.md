# РА «Лидер» — план преобразования CRM v3

Документ фиксирует новую логику работы CRM перед глобальными изменениями. Цель — перейти от перегруженной карточки заказа к понятному сценарию работы менеджера: заявка → потребность → сохранённый расчёт → КП → заказ → задачи → оплата → выполнение.

## 1. Главная цель преобразования

CRM должна быть удобной для менеджера, а не просто хранить данные.

Менеджер должен в любой момент понимать:

- кто клиент;
- что клиент хочет;
- что уже уточнено;
- что нужно уточнить;
- какие расчёты подготовлены;
- какое КП отправлено;
- что клиент согласовал;
- что нужно сделать дальше;
- есть ли предоплата;
- кто отвечает за дизайн, производство и монтаж;
- какой текущий статус заказа;
- есть ли долг, просрочка или проблема.

Основной принцип: CRM каждый раз показывает следующее действие.

## 2. Почему текущую логику нужно перестроить

Сейчас CRM уже содержит много полезных модулей: заявки, расчёт, заказы, финансы, история, дизайн, производство, монтаж. Но они начали накладываться друг на друга внутри одной страницы и одной раскрывающейся карточки заказа.

Риск текущего подхода:

- карточка заказа становится слишком длинной;
- несколько модулей одновременно внедряются в один DOM-блок;
- сложно понять, где заявка, где расчёт, где заказ;
- расчёт фактически привязан к созданию заказа;
- нельзя удобно хранить несколько вариантов расчёта в одной заявке;
- КП не является отдельным этапом согласования;
- менеджеру сложно ориентироваться в следующем действии.

Решение: не усложнять текущую карточку, а вынести подробные сценарии на отдельные страницы.

## 3. Новая базовая схема процесса

Новая логика:

1. Заявка.
2. Потребность клиента.
3. Сохранённый расчёт.
4. Коммерческое предложение.
5. Согласование.
6. Заказ.
7. Задачи: дизайн, производство, монтаж.
8. Оплаты и расходы.
9. Выполнение.
10. Закрытие.

Коротко:

Заявка = кто обратился и что примерно хочет.

Потребность = структурированное описание задачи клиента.

Расчёт = внутренний расчёт по номенклатуре, себестоимости, наценке и марже.

КП = понятное клиентское предложение без внутренней себестоимости и маржи.

Заказ = согласованный расчёт, принятый в работу.

## 4. Что делать с номенклатурой

Номенклатуру не нужно выбирать сразу в заявке.

Правильный подход — гибридный:

- в заявке менеджер фиксирует потребность простыми словами и понятными полями;
- CRM на основе потребности предлагает позиции номенклатуры;
- менеджер проверяет и корректирует расчёт;
- из расчёта формируется КП;
- из согласованного расчёта создаётся заказ.

Номенклатура — внутренний инструмент расчёта, а не форма для клиента и не первый экран менеджера.

## 5. Заявка

Заявка должна отвечать на вопрос: кто обратился и с чем?

Поля заявки:

- клиент;
- телефон;
- источник;
- первичное сообщение;
- тип потребности;
- статус заявки;
- статус контакта;
- следующий контакт;
- ответственный менеджер;
- город;
- комментарии;
- ссылки и файлы.

Быстрые действия в заявке:

- позвонить;
- написать в MAX;
- взять в работу;
- отметить «связались»;
- отметить «не дозвонились»;
- назначить следующий контакт;
- открыть потребность;
- создать расчёт;
- отказ;
- спам.

Статусы заявки:

- Новая;
- В работе;
- Не дозвонились;
- Уточнение деталей;
- Расчёт подготовлен;
- КП отправлено;
- Ждём ответ;
- Нужно пересчитать;
- Согласовано;
- Создан заказ;
- Отказ;
- Не отвечает;
- Спам.

## 6. Потребность клиента

Потребность — это структурированный блок внутри заявки.

Она должна быть простой для менеджера и не требовать знания номенклатуры.

Общие поля потребности:

- тип изделия или услуги;
- краткое описание;
- количество;
- срок;
- есть ли макет;
- нужен ли дизайн;
- нужен ли монтаж;
- адрес монтажа;
- комментарий клиента;
- внутренний комментарий менеджера;
- файлы и ссылки;
- статус полноты данных.

Примеры типов потребности:

- баннер;
- наклейки;
- табличка;
- вывеска;
- полиграфия;
- дизайн;
- монтаж;
- интернет-реклама;
- другое.

## 7. Сохранённые расчёты в заявке

Ключевое изменение: расчёт должен сохраняться в заявке даже без создания заказа.

У одной заявки может быть несколько расчётов:

- вариант без монтажа;
- вариант с монтажом;
- вариант с дизайном;
- эконом-вариант;
- премиум-вариант;
- новый расчёт после правок клиента.

Статусы расчёта:

- Черновик;
- Готов;
- КП сформировано;
- КП отправлено;
- На согласовании;
- Согласован;
- Отклонён;
- Создан заказ.

Действия с расчётом:

- открыть;
- редактировать;
- скопировать;
- пересчитать;
- сформировать КП;
- отметить КП отправленным;
- отметить согласованным;
- создать заказ.

## 8. Расчёт из потребности

Менеджер нажимает «Создать расчёт из потребности».

CRM анализирует тип потребности и предлагает позиции номенклатуры.

Пример для баннера 3×2 м:

- баннерная печать — 6 м²;
- проклейка края — 10 м.п.;
- люверсы — 20 шт.;
- дизайн макета — 1 проект, если макета нет;
- монтаж — 1 услуга, если монтаж нужен.

В расчёте менеджер видит:

- позицию;
- единицу измерения;
- количество;
- себестоимость за единицу;
- наценку;
- цену клиенту за единицу;
- сумму клиенту;
- маржу;
- комментарий.

Предупреждения:

- цена клиенту 0 ₽;
- себестоимость 0 ₽;
- маржа ниже 20%;
- заказ убыточный;
- нужен дизайн, но не добавлен;
- нужен монтаж, но не добавлен.

## 9. Наглядность наценок

Менеджер должен видеть наценку понятно.

Для каждой позиции:

- себестоимость;
- наценка в процентах;
- рекомендуемая цена клиенту;
- фактическая цена клиенту;
- прибыль по позиции;
- маржа по позиции.

Цветовые индикаторы:

- зелёный — маржа нормальная;
- жёлтый — маржа низкая;
- красный — убыточно;
- красный — цена клиенту 0 ₽.

Менеджер может менять цену клиенту вручную, но CRM должна показывать последствия.

## 10. Коммерческое предложение

КП создаётся из сохранённого расчёта.

Клиент не видит:

- себестоимость;
- внутреннюю наценку;
- маржу;
- цену подрядчика.

Клиент видит:

- что предлагается;
- что входит в стоимость;
- размеры, тираж, материалы;
- срок;
- итоговую стоимость;
- условия оплаты;
- что нужно от клиента;
- срок действия предложения.

Виды КП:

1. Короткое сообщение для MAX / ВК.
2. Подробное КП для согласования с начальством.
3. КП для печати / PDF, позже.

### 10.1. Короткое КП

Пример:

Здравствуйте! Подготовил расчёт.

Баннер 3×2 м с проклейкой, люверсами, дизайном и монтажом — 9 500 ₽.

Срок: 1–2 рабочих дня после согласования макета и предоплаты.

Для запуска нужно подтвердить заказ и внести предоплату.

### 10.2. Подробное КП

Структура:

- заголовок;
- клиент;
- дата;
- описание задачи;
- состав работ;
- характеристики;
- сроки;
- стоимость;
- условия оплаты;
- что нужно от клиента;
- примечания;
- срок действия предложения.

## 11. Создание заказа

Заказ создаётся только из согласованного расчёта.

Перед созданием заказа CRM проверяет:

- есть клиент;
- есть телефон;
- есть сохранённый расчёт;
- цена клиенту больше 0 ₽;
- есть позиции расчёта;
- понятен срок;
- понятен статус макета;
- понятно, нужен ли монтаж.

После создания заказа CRM предлагает создать связанные задачи:

- дизайн;
- производство;
- монтаж;
- контроль оплаты.

## 15. Адаптация сайта

Сайт не должен выбирать внутреннюю номенклатуру.

Сайт должен собирать первичную потребность:

- имя;
- телефон;
- тип услуги;
- комментарий;
- файл или фото;
- дополнительные поля, если клиент готов заполнить.

Типы услуг на сайте:

- Баннер;
- Наклейки;
- Вывеска;
- Табличка;
- Полиграфия;
- Дизайн;
- Монтаж;
- Реклама в интернете;
- Другое.

Дополнительные поля должны быть необязательными.

Задача сайта — быстро получить обращение, а не заставить клиента заполнить сложный калькулятор.

- проверять попадание заявки в CRM.

## 17. Правила безопасности преобразования

- не удалять старые таблицы;
- не ломать app-v2.html и app-v2-novpn.html;
- новые функции делать отдельными страницами;
- перед каждым этапом проверять аудит;
- сначала работать на тестовых заявках;
- заказ создавать только после проверки расчёта;
- старые заказы не мигрировать автоматически без необходимости.

## 18. Что считать успешным результатом

Преобразование успешно, если менеджер может пройти путь:

1. Открыть новую заявку.
2. Заполнить потребность.
3. Создать расчёт из потребности.
4. Сохранить расчёт без заказа.
5. Сформировать КП.
6. Отправить КП клиенту.
7. Отметить согласование.
8. Создать заказ из расчёта.
9. Создать дизайн / производство / монтаж.
10. Принять оплату.
11. Закрыть заказ.

При этом CRM должна ясно показывать следующее действие и предупреждать о рисках.
